# GCC Security Standards: Generative AI & Model Armor Hardening

## 1. Overview & Purpose

This document outlines **Google Cloud Consulting (GCC) Security** standards and best practices for securing Generative AI workloads, Large Language Models (LLMs), and Agentic applications using **Google Cloud Model Armor**.

---

## 2. Threat Matrix: OWASP Top 10 for LLM Applications

Model Armor directly addresses and mitigates the primary vulnerabilities identified in the OWASP Top 10 for LLM:

| OWASP Risk | Threat Description | Model Armor Mitigation Control |
| :--- | :--- | :--- |
| **LLM01: Prompt Injection** | Adversarial user prompts manipulating model execution. | **Prompt Injection & Jailbreak Filter** (`piAndJailbreakFilterSettings`) + Heuristic pre-screening. |
| **LLM02: Sensitive Information Disclosure** | Accidental leakage of PII, credentials, or proprietary data. | **Sensitive Data Protection (Cloud DLP)** inspect & de-identify templates. |
| **LLM06: Excessive Agency / Unauthorized Actions** | Autonomous agents executing harmful commands via tools. | **Tool Firewall** parameter inspection + Model Armor completion sanitization. |
| **LLM07: System Prompt Leakage** | Extraction of proprietary system instructions. | **System Prompt Canary Tokens** + Injection detection filters. |
| **LLM08: Vector & URL Poisoning** | Ingestion of malicious URLs and phishing payloads. | **Malicious URI Filter** (`maliciousUriFilterSettings`). |

---

## 3. Mandatory Security Controls & Baseline Requirements

### 3.1 Global FloorSetting Enforcement
- All Google Cloud projects hosting Generative AI workloads MUST enable Model Armor Global FloorSettings (`enableFloorSettingEnforcement = true`).
- Baseline FloorSettings MUST enforce at least `MEDIUM_AND_ABOVE` confidence thresholds for Prompt Injections, RAI filters, and Malicious URIs.

### 3.2 Least-Privilege IAM Roles
Model Armor access should follow the principle of least privilege:

| Role Name | Purpose | Assigned To |
| :--- | :--- | :--- |
| `roles/modelarmor.admin` | Full management of templates, floor settings, and policies. | Central SecOps Admins & CI/CD Pipeline Service Accounts. |
| `roles/modelarmor.editor` | Create and update templates within a project. | AI Platform Engineers. |
| `roles/modelarmor.user` | Execute prompt sanitization APIs (`sanitizeUserPrompt`, `sanitizeModelResponse`). | Application Runtime Service Accounts & Microservices. |
| `roles/modelarmor.viewer` | Read-only access to view template configs and audit metadata. | Security Auditors and Compliance Teams. |

### 3.3 Audit Logging & SIEM Integration
- `templateMetadata.logSanitizeOperations` MUST be set to `true`.
- Audit logs generated by Model Armor (`modelarmor.googleapis.com`) MUST be exported via Log Sinks to Google Security Operations (SecOps / Chronicle) or BigQuery for real-time threat detection and anomaly hunting.
